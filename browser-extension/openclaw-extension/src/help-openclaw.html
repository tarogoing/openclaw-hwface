How to enable OpenClaw API endpoints

OpenClaw Gateway often ships with `/v1/chat/completions` and `/v1/responses` disabled by default. This page explains what to turn on before testing the extension.

What this extension needs

The extension calls the Gateway directly. Plain text chat can use `/v1/chat/completions`, while attachments require `/v1/responses`.

Default behavior to watch for

If those endpoints are not enabled in your OpenClaw config, connection tests usually return 404, 405, or endpoint-disabled style errors.

Recommended setup steps

  1. 1. Open your OpenClaw Gateway config

    Find the configuration file or admin panel you use to start OpenClaw Gateway.

  2. 2. Enable the OpenAI-compatible chat endpoint

    Turn on the route for `/v1/chat/completions` if you want text-only compatibility mode in the extension.

  3. 3. Enable the Responses endpoint

    Turn on `/v1/responses` as well. This is the recommended mode for this extension, and it is required for images and other file attachments.

  4. 4. Restart or reload Gateway

    After saving the config, restart OpenClaw Gateway so the new endpoint switches take effect.

  5. 5. Test from the extension settings page

    Set the Base URL, choose `Responses API` or `Chat Completions API`, then click `Test Connection`.

Quick tips

  • If you only need normal text chat, enabling `/v1/chat/completions` may be enough.
  • If you want image upload or document upload, you must enable `/v1/responses`.
  • If your Gateway uses a token or password, fill it into `Gateway Token / Password` in the extension settings.
  • Keep your Base URL pointed at the Gateway root, for example `http://127.0.0.1:18789`.

Important note

Different OpenClaw versions may name the switches differently. If your config file does not use these exact labels, look for options that enable the OpenAI-compatible chat route and the Responses route.
